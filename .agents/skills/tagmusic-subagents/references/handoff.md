# 子 Agent 短交接协议

## 主 Agent 固定路由

一次派发交清目标与边界，批次完成或需决策时用五字段回传，不为卡片另建文件：

`交给=main；状态=实现完成；配置=无；输入=差异/结果入口@候选或工作项版本；注意=候选未构建，用户体验未测`

“配置”表示接收方请求档位：planner→planner；developer→simple/normal/high_risk；reviewer→acceptance/high_risk；command_runner→command_runner；phone_tester→phone_script/phone_visual；windows_tester→windows_gui；main→无。实际来源核 Agent 句柄；main 是协调目的地，不 spawn main。

| 情况 | 处理 |
|---|---|
| developer 实现/候选交付，或 runner/tester 完成 | 直接回 main 核对本批目标和结果，准备交用户体验，不自动追加 planner/reviewer |
| 具体修复/补查 | 优先原 developer/执行者，只传问题和本批差异 |
| 需求/依赖待决或技术困难 | main 读必要摘录，能直接解决就处理，必要时调用 planner |
| 关键证据冲突或需独立判断的明确风险 | 按需 reviewer / high_risk，给具体审查问题，不扩成全量验收 |
| 定位失败2次_已释放 | 原手机批次授权有效且旧控制者停控后转 phone_visual，见[手机执行](roles.md#手机执行) |
| 缺必要输入、版本不符、需授权/解锁/用户决策、失败/阻塞 | 停相关操作，补必要事实或交用户；不盲转卡片，不影响无依赖的已授权工作 |

状态可用就绪、实现完成、候选就绪、检查完成、审查通过、失败、阻塞；必须区分实现、运行与用户验收。“候选就绪”需说明构建/可运行的实际依据，未启动不得声称已运行。reviewer 启用时独立性和输入版本仍须核对，但审查通过不是所有普通批次的收口条件。

## 标题、摘要、内容

- 标题层为五字段；输入能定位本批差异/正文并标版本；注意显露影响交付的失败、未测、风险、授权或清理限制。
- 摘要仅给必要产品进度、授权或决策说明，不逐步回传。主可按需要读差异及短结果核对目标，不强制另派角色解释。
- 正文优先已有计划、差异与证据入口；短批次可直接附实际实现、剩余、检查/未测和候选入口。仅复杂设备批次或高风险核验才需要结构化结果表及证据映射，不为普通实现创建完整报告矩阵。

详细内容确需保存时只存一次，后续传引用；不把完整主聊天回灌给子 Agent，不为转述报告新建角色。常规小步骤不发消息；长批次有实质产品进展时简短更新已实现/正在实现/剩余，无需完整交接条。批次完成、具体阻塞、授权变化或失败门槛时再正式回传。主核对交付范围及证据边界，不能把“实现完成”宣布为用户验收通过。

## 派发提示词

> 你是 `<角色>`，项目 `D:\.projects\Tag Musicplayer`，请求配置 `<defaults模型/强度>`。交付 `<完整页面组/功能链>`；范围/不做 `<边界>`；输入 `<必要入口@版本及本批差异>`；预定验收范围与完成条件 `<可体验操作、必要检查及具体高风险>`。只写 `<路径>`；设备授权 `<本批明确授权或无>`；资源 `<占用/释放约束>`。按 AGENTS、SKILL 和 roles.md 自身小节连续完成，普通调用方/格式/编译修复自行处理，不追加测试矩阵。批次完成或需决策时回五字段及必要短结果。

spawn 显式 `fork_turns: none`、model、reasoning_effort；请求配置来自 [defaults.json](../defaults.json)，实际配置缺可信元数据记未验证。首次未落盘需求附必要原文，不只给不可读消息编号。角色使用、复用及排程见 [资源约束](../SKILL.md#派发与资源约束)。

设备批次由主或现有 developer 准备操作/预期、候选、执行者、工具限制、清理和停止条件；仅复杂待决批次才需 planner。按 [AGENTS.md](../../../../AGENTS.md) 交互确认影响范围及各端人工/Codex 选择；交接条不创造授权。手机定位升级安排提前说明，密码由用户处理。
