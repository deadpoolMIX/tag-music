# 子 Agent 短交接协议

## 主 Agent 固定路由

正常只读一行，不读正文、不猜标题用途：

`交给=developer；状态=就绪；配置=normal；输入=已有正文位置@版本；注意=无`

- 五字段缺失、接收角色未知或角色/配置不匹配：退回来源 Agent 补齐，不猜、不派发。
- `状态=就绪；注意=无`：交给指定角色，使用指定 defaults.json 配置，将输入引用原样传递；版本须对应当前工作项。
- `注意=定位失败2次_已释放`：仅在 phone_tester/phone_visual、原控制者已停止且原批授权有效时转 Terra/high，否则保持停止。
- `注意=风险未知`：交 planner；`注意=证据冲突`：交 reviewer/high_risk，不自行看代码或原图裁决。
- `注意=需授权/需解锁/需用户决策`：停止相关操作，只读来源提供的短授权/决策摘要并交用户；就绪标记不是授权。
- `状态=失败/阻塞` 或其他异常：停止正常推进，交明确指定的角色处理；去向不明则退回，不猜通过。
- `交给=main；状态=审查通过；配置=无；输入=审查依据@版本；注意=无`：只有实际来源为独立 reviewer、版本匹配且写入/设备资源已释放，才能收口。其他角色的完成只表示可交下一角色。

角色/配置白名单：planner→planner；developer→simple/normal/high_risk；reviewer→acceptance/high_risk；command_runner→command_runner；phone_tester→phone_script/phone_visual；windows_tester→windows_gui；main→无。main 仅为协调/授权/阻塞回报或审查收口的目的地，绝不 spawn 新 main；回 main 的状态只能为阻塞、失败或审查通过。缺输入或需授权时可回“交给=main；状态=阻塞；配置=无；输入=缺项或授权摘要所在位置@版本；注意=需授权/缺输入等具体标志”；没有现成位置的短说明直接附上，不为此新建文件。

## 标题、摘要、内容

- **标题层**是五字段短交接条。实际来源以 Agent 句柄确认；输入必须含可定位的正文/代码差异入口及候选、提交或工作项版本。配置编码已判定的执行档位，风险/配置理由放输入所指正文，由接收者和 reviewer 核验；未知/冲突写注意，主不另找风险字段，也不增加第六字段。
- **摘要层**可省略；只在沟通、授权、异常和决策需要时给几句话。失败、未测、风险、授权和清理限制必须在注意字段提示，不藏在摘要或正文。
- **内容层**由对应角色直接读必要部分，优先引用既有当轮计划、验收记录、精确差异和证据，不默认读整个目录。

交接条是一段消息/提示词，默认不落盘、不新建文件夹。短任务可直接附必要原文；长正文无现成入口且确需持久化时，由来源角色只保存一次，后续只传引用。已进入主聊天的文字无法因分层而消失，因此长正文不全文回传。交接条不能创造新授权；主仍掌握用户目标、阶段、配置、资源和阻塞。

## 交接去向

| 来源任务 | 下一角色 | 接收者需要的内容 |
|---|---|---|
| planner：实施计划 | developer | 原始需求、相关计划、必要实现入口 |
| developer：实现完成 | 原 planner | 原始需求、实际差异、完成/未完成项；不能只验收开发者声称完成的功能 |
| planner：测试计划 | command_runner 或对应端 tester | 本批步骤、定位、断言、证据、授权；多条独立任务给多条短交接条，不让主拆正文 |
| command_runner / tester | reviewer | 相关需求、差异、结果和原始证据 |
| reviewer：需修复/补测 | developer / planner / 原 tester | 针对性问题与必要上下文 |
| reviewer：完整通过 | main | 短交接条，正文留原处 |

已有有效计划、测试、审查按缺口更新，不每次重做。简单文档等任务跳过无关设备/构建角色。固定六类角色在同一完整工作单元内复用，单元收口后的上下文处理见 [Skill 派发与资源约束](../SKILL.md#派发与资源约束)，不新增“传文件”“写摘要”或“测试计划”角色。独立审查、Flutter 串行、一台设备一个控制者和写入所有权约束继续有效。

## 派发提示词

> 你是 `<角色>`，项目 `D:\.projects\Tag Musicplayer`，配置 `<defaults对应模型/强度>`，输入 `<引用@版本>`。遵守 AGENTS、Skill 公共边界及 roles.md 自身小节。只在已确认范围/指定路径内写入；设备授权 `<本批授权或无设备操作>`，资源 `<占用/释放约束>`。直接读本角色必要正文，完成只回五字段短交接条；缺项或越权则停止并返回。

使用 `fork_turns: none`，不附整段主聊天。首次输入若是未落盘的用户要求，必须附必要原文，不能只给其他 Agent 无法读取的聊天消息编号。请求配置以 defaults.json 为准，讨论中的拟定表不自动生效。

## 核验与必要例外

- planner/developer 判断技术风险，reviewer 独立复核；主按交接条执行路由，不先读正文再重写任务包。缺输入、版本不符或风险未知退回对应角色。
- reviewer 查实际需求覆盖、候选/输入版本、内容和原始证据，不只查文件存在或 done。审查者必须未参与实现；失败、未测、用户体验、计数和清理限制完整保留。只有完整通过才发审查通过/注意=无，否则标需用户决策或补查。
- 手机批次由 planner 另给5–8项操作、预期、候选、执行者、工具限制和清理边界的短授权摘要；主必须读取并向用户呈现，得到明确回复才派设备任务。密码仍由用户处理。
- 交接前确认旧 Agent 停止写入/控制，失败计数不清零；没有可靠停止信息就不派第二个控制者。用户暂停立即生效。

这是减少重复阅读的工作约定，不是文件访问隔离，也不保证固定的额度节省比例。主正常不读业务正文；用户决策确需时只读必要摘要，不重复专业角色的内容核验。
