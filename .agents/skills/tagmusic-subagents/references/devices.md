# 设备执行细则

仅准备或执行具体设备批次时读取。授权总则见 [AGENTS](../../../../AGENTS.md#实施与验证)，本文件不授予设备权限。

## 采集、手机与隐私

- GUI 批次按同一候选、授权范围和状态依赖连续组织，先列操作/预期、初始状态、证据及清理/恢复，电脑 Codex 测试一次交专用执行者。先用代表动作确认定位、输入及证据保存可用，再执行本批；不逐用例新增角色或默认交 reviewer。无法观察的体验留用户判断，失败或关键证据冲突按具体问题处理，不推广为全量检查。

- 视觉采集先按断言规划：每张截图对应新增状态或定位需要；初始定位及关键结果/不可逆状态留可辨认证据，稳定连续操作合并采集，并保留断言所需时序，不逐键、逐点击截图。失败、意外状态、定位不确定或需要确认前置条件时立即采集并停止或调整；不为压缩调用跳过必要观察。截图或快照按工具适用性选择，已知不安全的观测路径不原样重试；证据尽可能直接落盘，记录候选、步骤、时间及路径，不能落盘时说明来源和限制。不得以单一截图代替需要时间序列、数据或日志的断言。

- 手机端按该端选择执行。选“人工测试”后用户可立即开始操作手机；Codex 在用户开始后通过 ADB 只读监测可观察结果与日志，分析并记录，不发送输入或控制命令。无法由 ADB 判断的体验向用户收集，不凭日志推定通过。选“Codex 测试”时，Codex 按已确认的手机测试范围执行操作并记录结果。每轮手机测试提供 5～8 项操作及预期，按构建号收集“通过编号 / 失败现象 / 未测试”。手机锁屏且后续操作需要解锁时立即暂停设备控制，主Agent用交互选项询问“已解锁 / 暂不解锁”；仅收到明确“已解锁”后继续，Agent不得输入或绕过密码。

- 手机测试音频仅放在手机内部存储 `Download/tagmusic/<批次>/` 下，按批次创建子文件夹；不放Download根目录，不复用旧R5-17-PHONE-FINAL等杂乱路径。Android继续通过SAF URI访问，不推断真实路径、不申请全盘权限；每批记录实际`content://` URI与可观察授权状态，证据归档`artifacts/Rxx/`。不记录或外传私人/未知歌曲名称。

## 设备批次共同要求

主或现有 developer 按同一候选、授权范围和状态依赖准备简短连续批次，列操作/预期、初始状态、证据、清理/恢复和停止条件，复杂待决时才加 planner。影响操作及各端人工/Codex 选择依 AGENTS 交互确认；电脑 Codex 批次一次交专用执行者，人工测试只观察不代输入。先用代表动作验证定位、输入和证据保存可用，再执行；无法观察的体验留用户判断。

视觉采集遵守本文件的断言/时序规则，不逐点击截图、不重复取景；失败、不确定或意外状态及时留证并停/反馈，已知不安全观测路径不原样重试。日志/dumpsys 先在设备外本地筛相关字段/时间段，原始文件按需归批次证据，回传只给相关摘录、退出码、路径，不灌全量 UI 树。设备临时导出须先核对唯一专用路径及既有内容，禁用未检查的通用路径（如 `/sdcard/window.xml`）。

同一设备批次一个操作 Agent/控制者，不并行重复计划、证据整理或报告。执行结果记录候选、实际通过/失败/未测、异常累计、必要证据及清理/释放；按断言需要保留时序，不要求普通批次完整矩阵。完成停控后直接交 main，明确高风险或关键证据冲突才按需独立审查；唯一记录所有者集中更新，不重复写摘要。

## 手机执行

`phone_tester` 读本批测试正文/授权；明确脚本与可执行断言用 `phone_script`，复杂视觉判断/操作用 `phone_visual`，不宣称配置的项目实测表现已验证。仅走主机 PowerShell ADB，不依赖 Windows MCP 或其控制状态；ADB 不可用报告具体错误，不改走其他 UI 通道。开始核候选、设备、前置状态，不卸载、清数据或覆盖证据。

手机任务包须含候选版本/构建号与设备、5–8 项编号操作/预期、前置状态（是否需用户解锁）、允许/禁止影响操作、失败停止、证据路径和清理边界；短授权摘要另含执行者及工具不能判断的体验。人工测试仅用户开始后 ADB 只读监测，不控制；无法判断的体验向用户收集。范围/设备状态改变或新影响操作先停回主，不推导历史授权。

解锁、测试音频路径及隐私以 本文件“采集、手机与隐私”的条款为唯一规则：锁屏且需解锁即停，由主交互询问“已解锁 / 暂不解锁”，明确“已解锁”才续；Agent 不输入/绕过密码。音频仅 `Download/tagmusic/<批次>/`，SAF URI/授权状态及证据记录按该条款执行，不复用旧杂乱目录或记录私人/未知曲名。

Luna 截图定位升级：同一目标两次完整尝试仍不能确定正确控件/坐标，第二次即停输入，不做第三次 Luna 尝试。查看同一图不算新证据；第二次须有新截图/依据或改变方法。保存两次依据、目标、现场、已执行动作及累计，停控并释放后回“交给=phone_tester；状态=就绪；配置=phone_visual；输入=失败记录位置@版本；注意=定位失败2次_已释放”。主在原批授权有效时改派 `gpt-6.1-terra/high`，接收者先只读核现场再续行；切换不清计数、不增候选/操作/清理范围。Terra 不可用则阻塞，主不接管。锁屏、缺权限/授权立即停，不等两次；产品断言失败照实记录，不能以切模型掩盖。批次授权摘要须说明升级安排。

## 电脑 GUI 执行

`windows_tester` 固定 `gpt-6.1-terra/high` + Windows MCP，不能换 UI 通道。先读适用电脑操作 Skill、本批操作/预期及本批授权；配置/工具不可用回主，不替代或接管。按设备共同要求先验证代表动作及证据保存、再执行；人工测试仅观察。结果与证据映射、异常累计、清理/释放写必要结果，直接交 main；需独立判断时才加 reviewer；单图不能证明时序断言。
