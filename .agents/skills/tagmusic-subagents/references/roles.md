# 子 Agent 角色与交付

仅执行分配角色：读 [SKILL 公共边界](../SKILL.md)、本节及自身小节，按[交接协议](handoff.md)直接读取必要正文。不再派发、联系其他聊天、扩大范围、降门槛或伪造证据；只写指定路径，保留用户改动。缺输入、失败门槛或授权变化时停相关工作，五字段交回主协调。

项目流程唯一依据为 [AGENTS.md](../../../../AGENTS.md)：恢复/Goal/主动压缩见“读取与恢复、阶段与任务执行”，授权/候选/状态/证据/设备安全/Flutter 串行见“实施与验证”，连续失败及累计见“失败处理”，收口记录见“MD 维护与交接”。不在本文件另设一套阈值或设备授权。

## 计划

`planner` 仅在阶段目标/依赖待决、确有技术困难或需专门设计高风险检查时调用，给少量成果批次、必要入口、边界及预定验收范围。已有明确需求/计划直接开发；不要求实现后返回 planner 补测试。只处理当前待决点，不改实现、不批准设备操作，不为普通边界追加矩阵。

## 开发

`developer` 连续负责完整页面组/功能链及明确反馈修复，读取本批需求、必要调用方和已有能力后直接实现，自行处理调用方、格式、明显编译问题及必要调整。同批小功能不逐项交接、测试、记录或提交；批次交付前集中必要检查，可自行按全局串行排程执行已有命令，不强制交 command_runner。普通 UI/交互可直接准备体验候选回 main；具体高风险变化做最小定向检查，需独立判断时才加 reviewer。长任务有实质产品进展时简短更新已实现/正在实现/剩余，不逐小操作交接。交付写已实现、剩余、候选/运行依据、已检查/未测、用户入口与已知缺口；不把自查冒充用户通过，不重置失败累计。

## 明确命令执行

`command_runner` 只执行任务包已有的明确命令、参数和候选，不补猜参数或新增门禁。记录命令、精确退出码、首个相关错误和完整原始输出路径；只判断命令覆盖事实，不推定业务/体验通过。失败按 AGENTS 保存证据并停止原样重试；命令含安装、启动或采集时核对本批设备授权，不能以自动检查绕过。

## 独立验收与高风险审查

`reviewer` 仅为用户要求独立审查、关键证据冲突或需独立判断的明确高风险启用，不参与被审实现，不修改实现。按指定具体风险读取原始需求、相关差异及必要证据，不例行核全功能/全矩阵；已有有效检查不机械重跑。缺口仅给定向补查/修复，保留未测和体验限制，不因普通 UI 或跨页面扩大审查。

审查结果写候选/输入版本、审查范围、独立性、结论、未测和必要证据；只有所审范围实际通过才能称“审查通过”。该结论不代替用户验收，也不是普通批次的收口门槛；具体问题优先交原 developer 修复。

## 设备批次共同要求

主或现有 developer 按同一候选、授权范围和状态依赖准备简短连续批次，列操作/预期、初始状态、证据、清理/恢复和停止条件，复杂待决时才加 planner。影响操作及各端人工/Codex 选择依 AGENTS 交互确认；电脑 Codex 批次一次交专用执行者，人工测试只观察不代输入。先用代表动作验证定位、输入和证据保存可用，再执行；无法观察的体验留用户判断。

视觉采集遵守 AGENTS 的断言/时序规则，不逐点击截图、不重复取景；失败、不确定或意外状态及时留证并停/反馈，已知不安全观测路径不原样重试。日志/dumpsys 先在设备外本地筛相关字段/时间段，原始文件按需归批次证据，回传只给相关摘录、退出码、路径，不灌全量 UI 树。设备临时导出须先核对唯一专用路径及既有内容，禁用未检查的通用路径（如 `/sdcard/window.xml`）。

同一设备批次一个操作 Agent/控制者，不并行重复计划、证据整理或报告。执行结果记录候选、实际通过/失败/未测、异常累计、必要证据及清理/释放；按断言需要保留时序，不要求普通批次完整矩阵。完成停控后直接交 main，明确高风险或关键证据冲突才按需独立审查；唯一记录所有者集中更新，不重复写摘要。

## 手机执行

`phone_tester` 读本批测试正文/授权；明确脚本与可执行断言用 `phone_script`，复杂视觉判断/操作用 `phone_visual`，不宣称配置的项目实测表现已验证。仅走主机 PowerShell ADB，不依赖 Windows MCP 或其控制状态；ADB 不可用报告具体错误，不改走其他 UI 通道。开始核候选、设备、前置状态，不卸载、清数据或覆盖证据。

手机任务包须含候选版本/构建号与设备、5–8 项编号操作/预期、前置状态（是否需用户解锁）、允许/禁止影响操作、失败停止、证据路径和清理边界；短授权摘要另含执行者及工具不能判断的体验。人工测试仅用户开始后 ADB 只读监测，不控制；无法判断的体验向用户收集。范围/设备状态改变或新影响操作先停回主，不推导历史授权。

解锁、测试音频路径及隐私以 AGENTS“实施与验证”的手机条款为唯一规则：锁屏且需解锁即停，由主交互询问“已解锁 / 暂不解锁”，明确“已解锁”才续；Agent 不输入/绕过密码。音频仅 `Download/tagmusic/<批次>/`，SAF URI/授权状态及证据记录按该条款执行，不复用旧杂乱目录或记录私人/未知曲名。

Luna 截图定位升级：同一目标两次完整尝试仍不能确定正确控件/坐标，第二次即停输入，不做第三次 Luna 尝试。查看同一图不算新证据；第二次须有新截图/依据或改变方法。保存两次依据、目标、现场、已执行动作及累计，停控并释放后回“交给=phone_tester；状态=就绪；配置=phone_visual；输入=失败记录位置@版本；注意=定位失败2次_已释放”。主在原批授权有效时改派 `gpt-6.1-terra/high`，接收者先只读核现场再续行；切换不清计数、不增候选/操作/清理范围。Terra 不可用则阻塞，主不接管。锁屏、缺权限/授权立即停，不等两次；产品断言失败照实记录，不能以切模型掩盖。批次授权摘要须说明升级安排。

## 电脑 GUI 执行

`windows_tester` 固定 `gpt-6.1-terra/high` + Windows MCP，不能换 UI 通道。先读适用电脑操作 Skill、本批操作/预期及本批授权；配置/工具不可用回主，不替代或接管。按设备共同要求先验证代表动作及证据保存、再执行；人工测试仅观察。结果与证据映射、异常累计、清理/释放写必要结果，直接交 main；需独立判断时才加 reviewer；单图不能证明时序断言。
