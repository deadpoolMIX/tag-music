# Tag Music 严格协调

## 作用域与恢复

- 本项目开发、修复和测试默认使用，无需显式调用；普通问答或 Skill 评估不因此启动开发/测试派发。子 Agent 仅执行已分配角色及适用约束，不再次启动主协调流程。
- 只适用于绝对项目根 `D:\.projects\Tag Musicplayer` 及其子目录；先核对解析后的项目路径。项目外拒绝应用本 Skill，不向其他项目传播 Tag Music 规则；不修改全局 `subagents`。
- 先读本项目 `docs/HANDOFF.md`，核对分支、`git status --short --branch` 与相关提交，再按 `docs/README.md` 路由读取当前工作必要小节及适用 `AGENTS.md`。禁止全项目通读、默认加载历史报告或生成代码。交接不等于事实证明。
- 新阶段或产品重大变更继续依项目 Plan → 用户确认 → Goal；本 Skill 只协调已授权工作，不替代这些决策。Goal 状态不替代项目记录。

## 主 Agent 边界

主只负责用户目标、五字段短交接条、配置路由、授权、资源排程和状态；不开发、不修复业务、不运行质量测试或被测应用。流程文档、短交接条和协调元数据可由主维护；业务、测试和工具脚本以及普通文档交给指定 developer。主默认不读计划正文、代码、长日志、完整结果表或原图；正文核验与证据抽查交独立 reviewer。主核对输入版本、配置和注意标志、既有授权及实际来源的独立性，不另要求长风险字段；不能只见“完成”就宣布验收通过。异常按固定规则退回，用户决策或授权确需时只读必要摘要/摘录。

## 固定角色与分层交接

- 固定六类角色：`planner`、`developer`、`reviewer`、`command_runner`、`phone_tester`、`windows_tester`。风险和模型配置是角色内路由，不是新增部门；测试计划仍由 planner 制定，不新增“测试计划 Agent”。同角色同配置的串行任务优先复用原 Agent，切换模型、角色隔离或上下文失效时明确交接，不按功能名称无限新建 Agent。
- 必须使用 [交接协议](references/handoff.md)：默认回传五字段短交接条，直接写明接收角色和配置，主按固定规则转交，不猜标题含义；摘要按需，长正文引用已有文件/章节。交接条不必落盘，不默认新建任务文件夹、交接卡或重复报告。各角色额外只读 [自身边界](references/roles.md) 对应小节。
- 通常流程为 planner 实施计划 → developer 实现 → 原 planner 根据原始需求和实际差异细化测试 → command_runner/对应端 tester 执行 → 独立 reviewer 核验 → 主按卡收口。无设备或无实现的任务跳过无关角色，不机械运行整条流水线；已有效的计划/测试不重复制定。

## 配置与路由

读取 [defaults.json](defaults.json) 取得 `{model, reasoning_effort}`。它是本 Skill 自定义配置，不是 Codex 原生配置。主期望 Luna high，主界面配置由用户选择，本 Skill 不能自动切换或证明实际模型。派发参数与实际配置分别记录；无可信运行元数据时实际模型/强度写“未验证”。字段缺失、组合不支持或指定工具不可用时报告具体限制，不静默降档或主接管。

planner/developer 根据必要正文、实际差异和调用关系提交风险判断，reviewer 独立复核；主按交接卡和下表路由，不为判定常规任务而先读完整差异，也不要求用户先说任务“简单/复杂”：

| 客观触发器 | 配置/处理 |
|---|---|
| 数据库 schema/迁移、持久身份、SAF 权限、公共播放异步或 FD 生命周期、跨模块公共接口、证据矛盾 | 开发/独立审查用 `high_risk`；必要补读依赖，不扩大已批准测试范围 |
| 单文件文档，或明确且无业务语义的小 UI 变更 | 开发用 `simple` |
| 其余可界定实现 | 开发用 `normal` |
| 无法从已有入口确定风险或拆分 | 仅调用一次 `planner` 确定当前工作项角色配置；后续出现新风险升级，不每个子任务重开计划 |
| 执行已有且明确的自动检查命令，无需设计验收 | `command_runner` |
| 独立验收/解释证据 | `acceptance`；高风险代码审查用 `high_risk` |
| 手机已有明确 ADB 脚本/可执行断言及失败停止条件 | `phone_script`；需复杂视觉判断用 `phone_visual`；Luna 截图定位两次失败按角色规则升级 Terra，不扩大授权 |
| 电脑 GUI | `windows_gui`，必须 Windows MCP，项目强制 Terra high，不可替换 |

同一工作项高风险触发器优先于简单变更判定。确定性命令执行者不能替代独立验收；按任务需要启用角色，不机械创建全部角色。完整角色边界见 [references/roles.md](references/roles.md)，派发对应角色时读取。

风险判定与升级：

- planner 负责技术风险判定，developer 根据实际变更补充，reviewer 独立复核。短交接条的“配置”表示已判定的执行档位，“输入”指向含风险依据的正文；主只检查配置合法和注意标志，不单独读取风险等级或依据字段。未知风险标“注意=风险未知”，证据冲突标“注意=证据冲突”，按固定规则转交，不为每个小任务重开规划。
- 高风险按行为变化判定：改变数据库结构或旧库迁移、歌曲等持久身份、SAF 授权或 URI 语义、播放并发/异步状态与 FD 释放、跨模块公共接口，命中任一项即使用 `high_risk`（当前为 `gpt-6.1-sol / high`）。证据矛盾的独立审查同样使用 `high_risk`；仅在文档中提及这些词或无语义变化的格式调整不构成命中，不因计划详细或改动行数少而降级。
- 命中/排除理由留正文，由接收者和 reviewer 阅读，不增加第六字段。执行者发现新触发项或判定矛盾时暂停相关变更，回五字段短交接条并标注意；主按固定规则重新路由，技术争议交 planner/reviewer。切换配置前须确认旧 Agent 已停止写入，保留失败计数与独立审查边界。
- 配置升级不扩大任务、架构或设备授权；命中高风险触发项时保持 `high_risk`，执行者不得自行降级。模型选型讨论中的拟定表不替代 `defaults.json`，尚未确认的执行配置不自动落盘。

## 派发与资源约束

- 每个子 Agent 显式 `fork_turns: "none"`，显式传 model 和 reasoning_effort，task_name 仅小写字母、数字、下划线。不能默认继承主上下文；每个子 Agent 禁止再派发子 Agent 或自行联系其他聊天。
- 派发只给短交接条与必要的公共边界：项目、角色/配置、输入引用、允许写入范围、授权和资源状态；长正文由输入指向已有文件/章节，不在主聊天复述。短任务可直接附必要原文，不为规避几句话而新建文件；没有持久入口的长内容仅由来源角色保存一次。缺失必要输入/授权则退回，不把历史全文塞入任务包。
- 手机任务包在派发前一次列清：候选版本/构建号与设备、5–8项编号操作及预期、开始前状态（包括是否需要用户先解锁）、允许/禁止的影响操作、失败停止条件、证据存放位置与清理边界。锁屏密码由用户自行处理，Agent不输入、不绕过。测试范围或设备状态变化时先停并回主协调，不从历史授权推导新范围。
- 手机执行只走主机 PowerShell ADB；手机 Agent 不依赖 Windows MCP，也不因 Windows MCP 控制状态单独阻塞 ADB。Windows MCP 仅用于电脑 GUI，电脑 GUI 仍按 `windows_gui` 规则执行。ADB 本身不可用时，报告 ADB 的具体错误，不擅自切换到另一种界面控制渠道。
- 证据按断言采集：每个新状态或定位需要保留可辨认证据，稳定连续动作可合并；不逐点击截图，不为多留图而重复取景。日志和 dumpsys 先在设备外本地筛选与断言相关的字段/时间段；完整原始文件按需存入批次证据目录，主上下文只传相关摘录、退出码和文件路径。设备端写入临时文件前必须核对唯一专用路径及既有内容；禁止使用未检查的通用路径（例如 `/sdcard/window.xml`）作为导出目标。
- 单台手机的同一批次只设一个操作 Agent 和一个设备控制者；不并行派发重复计划、证据整理或报告撰写。操作 Agent 写好正文结果表和证据索引、停止写入后，主按卡交给独立 reviewer；reviewer 按风险核验原始证据，正常批次可合并审阅，不机械每条用例新建审查。主依据审查卡指定一个文档所有者集中收口，不重复整理正文或另建平行摘要。
- 最多同时运行 3 个子 Agent。可并行无依赖的只读审阅；写文件所有权不得重叠，集中记录在子 Agent 停止写入后由主更新。所有 Flutter 检查、测试、构建全局串行；一台设备同一时刻只有一个执行者，安排明确占用与释放，后台监测也不得与控制者冲突。
- 同一工作项的独立验收/审查不得由参与该实现或修复的 Agent 承担。原开发 Agent 与原验收 Agent 可分别复用并接收本批差异，不跨角色复用；角色需要变更时新建 `fork_turns: "none"` 上下文，仍须遵守前述开发参与者排除规则，并保留既有测试失败计数。失联时保留状态，不能猜测其已停止写入；需更换时明确交接边界。

## 授权、测试与失败

- 批次授权、人工/Codex 测试、暂停、产品状态、证据和失败处理统一遵守项目 `AGENTS.md`；默认加载或显式调用 Skill 均不构成设备授权或恢复暂停任务。
- 仅执行已批准测试范围，不新增已忽略门禁，不把构建成功或开发自查当独立验收；未验证项明确保留。
- 工具/配置不可用时报告具体限制，完成无依赖的已授权事项后停止，不擅自更换配置或接管界面。

## 回传与记录

- 子 Agent 常规只回五字段交接条；异常仅在“注意”字段标需处理的风险、授权、定位升级或失败，不把正文、结果表、代码 diff 或长日志回灌主聊天。候选/提交、断言明细、异常累计、证据映射、未验证边界与清理详情留已有正文，由接收角色按职责读取；证据不足不能记通过。
- 记录、交接和收口遵守 `AGENTS.md` 的 MD 维护与交接规则；复用现有当轮记录，补必要的 Agent 标识、请求配置、任务/路径所有权及失败累计，不另建平行日志。收尾说明交付、验证边界、未决项和证据入口，不宣称未发生的独立验收或主动压缩。
