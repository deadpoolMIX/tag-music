# Tag Music 严格协调

## 作用域与恢复

- 先核对解析后的项目路径；仅用于项目根 `D:\.projects\Tag Musicplayer` 及子目录；项目外拒绝应用，不传播项目规则，不改全局 `subagents`。开发、修复和测试默认使用；普通问答或 Skill 评估不因此启动开发/测试。子 Agent 只执行已分配角色，不启动协调或再派发，也不自行联系其他聊天。
- 读取、恢复、Plan → 用户确认 → Goal、续行与暂停、批次授权、失败处理、产品状态、文档维护和压缩，统一遵守项目 [AGENTS.md](../../../AGENTS.md)。先读 [HANDOFF](../../../docs/HANDOFF.md) 并核对实际分支、状态和相关提交，再沿必要入口读取；交接不是事实证明。本 Skill 不恢复暂停任务、不替代阶段决策、不产生设备授权。
- 主只管用户目标、五字段交接、配置路由、授权、资源与状态，不开发/修复业务、不运行质量测试或被测应用。主可维护流程文档和协调元数据；业务、测试、工具脚本及普通文档交 developer。主正常不读计划正文、业务代码、长日志、结果表或原图，内容与证据核验交独立 reviewer；仅在授权、用户决策或异常处理中读必要摘要/摘录。

## 角色、配置与路由

按需启用六类角色：`planner`、`developer`、`reviewer`、`command_runner`、`phone_tester`、`windows_tester`；不建满流水线，不按功能无限增设角色。测试计划仍由 planner 制定。必要时拟新增岗位或 Skill，须先由主向用户说明并请示；明确同意后才创建，并将职责、配置、路由/交接规则或新 Skill 入口同步写入本 Skill 对应文件。跨项目复用搁置至本项目完成；当前仍严格限上述路径。

[defaults.json](defaults.json) 是自定义配置的唯一来源，不是 Codex 原生配置。主期望 Luna/high，由用户在界面选择，Skill 不能切换或证明实际模型。派发参数与实际配置分别记录；缺可信运行元数据时实际模型/强度写“未验证”。缺字段、不支持的组合或工具不可用须报告，不静默替换、降档或由主接管；讨论中的拟定表不自动落盘。

| 工作项 | 配置/处理 |
|---|---|
| 数据库结构/旧库迁移、歌曲等持久身份、SAF 授权/URI 语义、播放并发/异步状态或 FD 释放、跨模块公共接口的行为变化 | developer/reviewer 用 `high_risk`，必要补读依赖 |
| 证据矛盾 | reviewer / `high_risk` |
| 单文件文档，或明确且无业务语义的小 UI 变更 | developer / `simple` |
| 其余可界定实现 | developer / `normal` |
| 不能确定风险或拆分 | 调一次 planner 确定当前项路由，不逐小任务重开规划 |
| 已有明确自动检查命令，无需设计验收 | `command_runner`，不能替代独立验收 |
| 独立验收/解释证据 | reviewer / `acceptance`，高风险仍用 `high_risk` |
| 手机明确 ADB 脚本/可执行断言及停止条件；复杂视觉操作 | `phone_script`；`phone_visual`，定位升级见[手机执行](references/roles.md#手机执行) |
| 电脑 GUI | `windows_gui`，必须 Windows MCP + `gpt-6.1-terra/high`，不可替换 |

planner 判风险，developer 按实际差异补充，reviewer 独立复核；命中/排除理由留正文，主只核对配置、版本、注意标志和既有授权，不另索风险字段。高风险优先，不因计划详尽、行数少而降级；仅提及术语或无语义格式调整不算触发。新触发项/判定矛盾须暂停相关变更并按[交接协议](references/handoff.md)回传，技术争议交 planner/reviewer。切配置先确认旧 Agent 停写，保留失败计数和独立审查；升级不扩大任务、架构或设备授权，执行者不得自行降级。

## 派发与资源约束

- 每次 spawn 显式 `fork_turns: "none"`、model、reasoning_effort；task_name 仅小写字母、数字、下划线。只传[五字段及必要公共边界](references/handoff.md#派发提示词)，长正文引用已有入口，不灌入整段主聊天。接收者读 [roles.md](references/roles.md) 公共约束及自身小节；设备任务另读共同执行要求。
- 最多同时 3 个子 Agent；可并行无依赖只读审阅，写路径所有权不重叠，集中记录待执行者停写后更新。Flutter 检查、测试、构建全局串行；设备同一时刻一个执行者/控制者，明确占用和释放，后台监测不得冲突。
- 独立 reviewer 必须未参与本项实现/修复。同一完整工作单元内，同角色同配置串行任务优先复用原 Agent，只补本批差异；不跨角色复用。切模型、隔离角色或上下文失效时新建 `fork_turns: "none"` 并交接，不能绕过开发参与者排除。失联不等于停写，更换前须确认边界，失败计数不清零。
- 完整单元按 AGENTS 的压缩条件收口：相关验证与独立审查、必要记录/检查点及核对、执行者停写/释放均完成后，不再向本单元 Agent 派发或发消息；下一单元按需新建，只传必要入口和当前差异。修复、补测、收口核对仍属原单元，不按单条操作换 Agent。这不删除历史、不等于压缩子 Agent、不抹去主已收到内容/失败计数；闲置不等于持续运行，不承诺固定额度节省。运行时限制新建且无释放入口时报告，不跨单元复用或宣称清空。
- 仅做已批准范围，不新增已忽略门禁，不把构建/自查当独立验收；证据不足或工具/配置未验证必须保留限制。受阻时完成无依赖的已授权事项后停止，不接管界面。

## 交付入口

通常为 planner 实施计划 → developer → 原 planner 按原始需求与差异补测试 → command_runner/端 tester → 独立 reviewer → 主收口；无关角色跳过，有效计划/检查按缺口更新。

所有回传、异常路由、正文职责与派发模板仅见[交接协议](references/handoff.md)。当轮文档仅维护当前计划、必要规格与缺口，HANDOFF 仅维护当前状态与下一步及必要入口；工作单元完成摘要唯一写入开发日志，每单元一行，禁止在其他 Markdown 重复写流水账、开发过程或详细验证叙事。Agent 标识、请求/实际配置、任务/路径所有权、失败累计和详细执行/审查证据随原始报告留 `artifacts/Rxx/`；正式验收结论按项目索引职责记录，不建平行日志，不宣称未发生的验收或主动压缩。
