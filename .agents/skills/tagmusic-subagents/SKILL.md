# Tag Music 严格协调

## 作用域与恢复

- 仅在用户明确调用 `$tagmusic-subagents` 或明确要求采用本项目专用协调流程时启动；普通事实咨询、Skill 评估或无关请求不启动开发/测试派发。
- 只适用于绝对项目根 `D:\.projects\Tag Musicplayer` 及其子目录；先核对解析后的项目路径。项目外拒绝应用本 Skill，不向其他项目传播 Tag Music 规则；不修改全局 `subagents`。
- 先读本项目 `docs/HANDOFF.md`，核对分支、`git status --short --branch` 与相关提交，再按 `docs/README.md` 路由读取当前工作必要小节及适用 `AGENTS.md`。禁止全项目通读、默认加载历史报告或生成代码。交接不等于事实证明。
- 新阶段或产品重大变更继续依项目 Plan → 用户确认 → Goal；本 Skill 只协调已授权工作，不替代这些决策。Goal 状态不替代项目记录。

## 主 Agent 边界

主只负责范围、风险路由、授权、派发、状态、结果核对和证据抽查；不开发、不修复业务、不运行质量测试或被测应用。流程文档、任务包、协调元数据可由主维护；业务、测试和工具脚本交给有明确所有权的子 Agent。普通文档交付同样由开发子 Agent 修改；主可查事实、评审结果，不将协调元数据例外扩展为文档代写。主必须核对结果表及证据索引并按风险抽查关键原始证据；缺口、矛盾或高风险疑点扩大复核并定向派发，不能只检查报告非空，也不能把摘要当原始证据。

## 配置与路由

读取 [defaults.json](defaults.json) 取得 `{model, reasoning_effort}`。它是本 Skill 自定义配置，不是 Codex 原生配置。主期望 Luna high，主界面配置由用户选择，本 Skill 不能自动切换或证明实际模型。派发参数与实际配置分别记录；无可信运行元数据时实际模型/强度写“未验证”。字段缺失、组合不支持或指定工具不可用时报告具体限制，不静默降档或主接管。

协调者根据实际差异、调用方和验收风险路由，不要求用户先说任务“简单/复杂”：

| 客观触发器 | 配置/处理 |
|---|---|
| 数据库 schema/迁移、持久身份、SAF 权限、公共播放异步或 FD 生命周期、跨模块公共接口、证据矛盾 | 开发/独立审查用 `high_risk`；必要补读依赖，不扩大已批准测试范围 |
| 单文件文档，或明确且无业务语义的小 UI 变更 | 开发用 `simple` |
| 其余可界定实现 | 开发用 `normal` |
| 无法从已有入口确定风险或拆分 | 仅调用一次 `planner` 确定当前工作项角色配置；后续出现新风险升级，不每个子任务重开计划 |
| 执行已有且明确的自动检查命令，无需设计验收 | `command_runner` |
| 独立验收/解释证据 | `acceptance`；高风险代码审查用 `high_risk` |
| 手机已有明确 ADB 脚本 | `phone_script`；需视觉定位/操作用 `phone_visual`，这不是手机操作优越性的实测结论 |
| 电脑 GUI | `windows_gui`，必须 Windows MCP，项目强制 Terra high，不可替换 |

同一工作项高风险触发器优先于简单变更判定。确定性命令执行者不能替代独立验收；按任务需要启用角色，不机械创建全部角色。完整角色边界见 [references/roles.md](references/roles.md)，派发对应角色时读取。

## 派发与资源约束

- 每个子 Agent 显式 `fork_turns: "none"`，显式传 model 和 reasoning_effort，task_name 仅小写字母、数字、下划线。不能默认继承主上下文；每个子 Agent 禁止再派发子 Agent 或自行联系其他聊天。
- 给出自足短任务包：绝对项目/输入路径、本批目标和差异、角色及配置、适用公共/角色约束、必读入口与必要行段、允许修改路径、排除项、验收与已批准测试范围、设备/候选/本批授权、证据目录、失败累计信息、回传要求。不得只给一个路径而省略必要授权和角色约束，也不把主聊天或历史全文塞入任务包。
- 最多同时运行 3 个子 Agent。可并行无依赖的只读审阅；写文件所有权不得重叠，集中记录在子 Agent 停止写入后由主更新。所有 Flutter 检查、测试、构建全局串行；一台设备同一时刻只有一个执行者，安排明确占用与释放，后台监测也不得与控制者冲突。
- 同一工作项的独立验收/审查不得由参与该实现或修复的 Agent 承担。原开发 Agent 与原验收 Agent 可分别复用并接收本批差异，不跨角色复用；角色需要变更时新建 `fork_turns: "none"` 上下文，仍须遵守前述开发参与者排除规则，并保留既有测试失败计数。失联时保留状态，不能猜测其已停止写入；需更换时明确交接边界。

## 授权、测试与失败

- 严格使用当前项目 `AGENTS.md` 的批次授权、人工/Codex 测试、暂停与证据规则。影响电脑/手机的操作前，交互式列明本批候选、操作、预期、执行者、不可观察体验和清理边界，等待明确回复；旧批许可和 Skill 调用不是新批授权。
- 电脑 Codex 操作由主直接派专用 Windows MCP 子 Agent；人工测试时只观察记录，不控制。手机人工测试只允许用户开始后 ADB 只读监测，不发送输入；Codex 手机测试限已批准范围。手机每轮 5～8 项，按构建号收集通过/失败/未测。
- 只执行用户批准的测试范围。Skill 不新增已忽略门禁，不把构建成功或自查当双端验收；未验证项明确保留。产品状态沿项目“开发中 → 自动验证通过 → 待手机验收 → 双端通过”，暂停/阻塞另记。
- 同一问题连续失败两次，立即汇报现象、已试方法、证据和阻塞，停止原样重试；再次执行必须有新证据、明确假设或改变方案，且仍在授权内。保存首个相关错误、退出码及上下文，缩小复现。累计失败跨候选、批次和对话保留；没有固定三轮必转人工，也不能换 ID 清零。
- 用户暂停或收窄范围立即生效；只等待已知活动句柄。工具/配置不可用时报告具体限制，完成无依赖的已授权事项后停止，不擅自更换配置或接管界面。

## 回传与记录

- 子 Agent 常规只回短表：候选/提交、断言或任务、通过/失败/未测、异常与累计次数、原始证据路径、未验证边界、清理与资源释放。详细原始输出直接保存，不将长日志反复回灌主上下文；证据不足不能记通过。
- 复用 `docs/rounds/Rxx.md` 当前计划和技术记录、对应验收记录及 `artifacts/Rxx/` 原始证据；不新建三规范、三日志、平行 DEVLOG/ISSUE-SUMMARY。仅在现有当轮记录补必要的 Agent 标识、请求配置、任务/路径所有权和失败累计元数据。证据一处保存，其他文档引用。
- 主集中核验后更新当轮记录与唯一 HANDOFF，完成相关检查点；`docs/开发日志.md` 收口一句已完成摘要。遵守项目本地 Git、产物不提交和压缩/暂停规则。收尾说明交付、验证边界、未决项和证据入口，不宣称未发生的独立验收或主动压缩。
