# R2 手机验收清单

最新候选版本：**0.3.0+11**。+10用户反馈搜索不能弹键盘/粘贴，验收失败；其余已测功能正常。+11输入及后续6项手测已收到用户通过反馈，证据见artifacts/R2/android11/run-20261030-1609/user-feedback.json；阶段状态以HANDOFF为准。构建及安装状态以 HANDOFF 为准。安装必须原签名覆盖，不卸载、不清数据。

1. **覆盖升级与启动**：升级后打开应用，主题和此前目录授权保留；没有自动播放。R1只有临时列表，升级后首次需要扫描已有目录，扫描后才建立持久曲库。
2. **多目录递归**：添加两个音乐文件夹，其中一个含子文件夹；扫描完成后两处的歌曲都出现。重叠选择其中子目录，不应重复入库。同一音频复制到不同位置会作为两条记录，R2不按音频内容合并文件。
3. **重复和增量刷新**：再次刷新同一目录，歌曲总数不变，界面报告只重读新增/修改/此前坏文件的元数据；更新一首或新增一首，再刷新能看到变化。
4. **取消与可操作性**：扫描较大目录时搜索、滚动或播放；界面可操作。点击“取消扫描”，未完成目录保留扫描前的曲库；已完整完成的其他目录仍保留结果。重新刷新可完成导入。
5. **坏文件和封面**：包含坏MP3的目录仍能完成扫描，坏文件退回文件名并显示信息图标；正常歌曲可播放，含有效内嵌图片的歌曲在播放器显示封面，无封面则显示唱片占位。
6. **搜索排序与播放独立**：搜索歌曲/歌手/专辑/文件名，切换排序和升降序；无匹配时显示空结果。播放一首后更改搜索、排序或刷新，当前播放不中断，原播放快照保持。
7. **重启持久化**：关闭再打开应用，曲库和目录仍在，无需重新扫描，默认不播放；主题保持。R2不包含R5的队列和进度恢复。
8. **文件失联与恢复**：将一首测试文件暂时移出已选目录，完整刷新后该歌曲显示失联，记录保留且不能点击播放；放回原位置并刷新后恢复可用。目录权限失效时提示失败并保留旧记录。勿对珍贵原文件作破坏性操作。

反馈格式：构建号；通过编号；失败编号及现象；未测试编号。失败由助手收集日志和修复。Windows Release已使用实际桌面操作、截图和输出回环补验；与原生Debug证据分别记录，见HANDOFF。

## +11 输入修复的手动复验

同一搜索问题已有两次自动失败及用户手动失败；助手不再自动重复搜索测试，后续由用户操作，助手抓日志和修复。

1. 点击搜索框：正常弹出键盘，能看到输入光标。
2. 输入 `flac`：使用原16首样本库时显示3/16首；曲库已变则按实际含flac文件数核对。
3. 记下当前总数N；清空后输入不存在的词：显示空结果，点击“清空搜索”恢复N首。
4. 复制任意搜索词，长按输入框：粘贴可用，结果随文本变化。
5. 隐藏键盘后再次点击搜索框，或切到设置后返回：可以继续编辑，搜索词与显示结果一致。
6. 播放正常歌曲后搜索/清空、切排序：当前播放继续；关闭重开仍保留N首和授权，不自动播放。
