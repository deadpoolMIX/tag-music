# 本聊天待测清单：R6 / 0.6.0+25

先完成 A1，再按 A～E 顺序测试。只测25号，不必把18～24号逐包重测。

## 范围与完成口径

这份清单把本聊天各批次未测的人工体验合并为25个功能检查组，不等于25个按钮；每组列出的子场景都属于该组。新发现的问题归原编号修复和回验，不借收尾增加无关功能。

Windows和Android分别填：`通过 / 失败（现象）/ 未测（原因）/ 不适用（具体子场景）`。一个平台的通过不能代替另一个平台。键鼠快捷键仅适用于有键鼠的设备，手机仍须测触屏/系统返回/读屏等对应操作。

“本聊天工作关闭”条件：适用项目通过；失败已修复并定向回验，或由用户明确接受保留；未测项已补测或由用户明确接受延期。测过但失败、跳过或未复现，均不能自动记为通过。两端结果和必要技术缺口处理完，由用户明确确认后，才记R6阶段验收通过。

当前所有格子均为“待测”，本文没有登记任何新的测试通过，也不恢复Codex手机操作授权。

## 开始前准备

1. 使用[Windows EXE](../../artifacts/R6/experience-build-25/windows-25/tag_music.exe)或[Android APK](../../artifacts/R6/tag-music-0.6.0+25.apk)。版本0.6.0+25，包内revision `01d6547`。电脑由用户自行启动；手机由用户自行覆盖安装，保留数据，不卸载/清数据。
2. 基础原创样本在[experience20目录](../../artifacts/R6/sleep-timer-batch/experience20/)：R6-A为UTF-8双语/附加歌词且有封面，B为UTF-16LE带BOM歌词，C为不支持编码，D无歌词；音频各24秒。使用小音量。手机路径须是手机实际目录，通过系统目录选择授权；电脑路径不能直接当作手机路径。
3. 准备专用临时标签、普通/智能歌单，用它们验证新增/编辑/删除，保留既有音乐和记录；无需删除R5已接受保留的三条失联记录，也不恢复旧目录/XML清理。
4. 补充分支需要相应输入：长名称/未知字段/重复歌曲/足够滚动的列表、坏或超大封面、无时间戳/损坏/超限LRC、可产生慢装载/缓冲或读取失败的条件。基础A～D不覆盖这些分支；没有输入就标未测，后续由Codex准备输入或双方明确延期，不能写通过。不要求用户自己写脚本、破坏音乐或撤销现有目录授权制造故障。
5. 首先按正常窗口/默认字号跑流程；再以深浅主题、大字号、窄/宽/短窗口或手机横竖屏复查对应页面。每组的尺寸变体归原编号，不重复建第二份清单。系统有“减少动画”选项时检查D5。
