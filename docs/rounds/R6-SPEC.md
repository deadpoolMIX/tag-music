# R6 详细产品与技术规格

按本批任务只读相关小节，不默认通读。当前目标、批次、进度和缺口唯一见 [R6](R6.md)；§四/§五及§2G指其执行计划、验收范围和当前缺口。本文不恢复暂停阶段。

## 二、界面与交互规格

### 1. 导航和页面结构
- 手机使用左侧约半屏抽屉。主界面支持菜单按钮，曲库和独立搜索等页面支持从内容区向右滑动打开。播放页和歌词页停用右滑开侧栏。独立页面上关闭侧栏可回到原页面，选导航项会进入对应主页面。
- Windows 左侧导航常驻，参考桌面音乐软件的清晰分区；窄窗口压缩为图标栏，保留提示文字。
- 导航依次为：**歌曲、筛选、歌单、专辑、歌手、标签、设置**。
- 参考图2的圆角分组容器、统一图标对齐、选中反馈和留白，将业务入口与设置作视觉分组，保留上述七入口及顺序；目录管理仍在设置，不照抄文件夹、扫描、统计等新入口或随机顶栏。
- 手机抽屉打开时后方页面仍可辨认；minibar 固定在底部，不随菜单横向移动。桌面仍为常开左栏。
- 删除顶部软件名称和阶段标识，版本及诊断信息保留在设置。
- 切页和详情返回保留本次运行中的列表位置、排序与浏览状态，不新增跨启动恢复。
- 筛选右上角使用无底色的「保存为智能歌单」图标，下方三框同排，框内左上角以 `∧`、`∨`、`−` 分别标记同时包含、包含其一、排除。点框选择或取消标签，已选项显示为胶囊。结果区保留歌曲列表和筛选记录异常时的恢复入口。
- 筛选标签弹窗顶部显示可点按取消的已选胶囊。下方的可选标签按歌曲数降序排列，以双列共用一条竖向滚动列表。选中即移出可选区，确认后应用，取消放弃草稿。
- 浅色页面以纯白为主背景。设置可选海蓝、紫色、玫红和琥珀，默认海蓝。主题色与浅色、深色、跟随系统的选择分别保存。
- 标签页创建和名称排序合为一行。歌手、专辑页在导航键同一行显示标题及排序，专辑行使用第一张可读的歌曲内嵌封面。歌单页在同一顶栏右侧显示名称排序和无底色的新建歌单图标。智能歌单从筛选结果保存，整队列保存入口位于队列。
- 通用弹窗收紧标题、内容、按钮的留白。标签、歌单和歌曲选择器随内容收起、长列表可滚动，搜索框使用紧凑内距。

歌曲首页布局确定为：

| 位置 | 内容 |
|---|---|
| 第一行 | 手机菜单按钮、页面名“歌曲”、右侧搜索按钮 |
| 第二行左侧 | 排序小图标、刷新按钮 |
| 第二行右侧 | `xx首` |
| 主体 | 紧凑歌曲列表 |
| 右下角 | 半透明“定位当前歌曲”按钮 |
| 底部 | 全局 minibar |

首页不再常态显示多选、添加文件夹、保存列表等按钮。添加文件夹及目录管理移到设置；扫描进度、取消及失败信息只在相关状态出现。

### 2. 共享歌曲列表
建立统一的歌曲行和列表组件，首页、搜索、专辑详情、歌手详情、标签详情、歌单详情共同使用。以后修改该组件，相关页面同步改变。
- 左侧约 **44dp 圆角封面**。
- 中间上方：歌名，**16sp、常规字重、单行省略**。
- 下方：`歌手－专辑`，约 **12sp**，弱化颜色。
- 右侧依次为 **＋、更多菜单**。
- 正常字号下行高目标约 **60dp**；系统放大字体时允许增高，不强行裁切。
- 图标可以小，但交互区域至少保留 48dp。
- 正在播放项用主题色和轻量状态标识区分，不使用音质徽标。

操作保持已有语义：
- 点击歌曲：按当前列表生成播放快照。
- ＋：复用 R5 优先待播 FIFO，连续加 A、B，先 A 后 B，再续原队列。
- 长按：进入多选；桌面同时提供右键及菜单中的多选入口。
- 更多菜单：标签、加入歌单、歌曲信息等单曲操作。
- 多选后：显示专用操作栏，提供全选、批量标签、加入队列、保存歌单及退出。
- 普通歌单的移除、重排，智能歌单的编辑规则等功能保留，通过对应模式和菜单进入。

定位按钮只处理当前列表：存在当前歌曲时滚动并短暂高亮；不在列表时禁用，不切页、不清除筛选。

### 3. 排序、搜索与分组页
**首页排序**
- 图标打开底部半页面板，双端均不再使用小下拉框。
- 选项仅为：**歌名、歌手、修改时间**，另选升序或降序。
- 默认采用**修改时间降序**；未知时间始终排尾，同值采用稳定次序。
- 不新增“添加时间”，不把文件修改时间称作添加时间。
- 保留旧筛选和智能歌单中已保存的专辑、文件名排序语义，不覆盖旧配置。

**独立搜索**
- 右上角进入独立页面，搜索全曲库的歌名、歌手、专辑、文件名。
- 复用共享歌曲列表，查询状态独立，返回后不改变来源页面的搜索、排序和位置。
- 搜索结果播放及添加队列继续采用结果快照。

**标签、歌手、专辑、歌单**
- 共用紧凑分组列表：名称、歌曲数、必要的更多菜单。
- 分组列表默认按名称升序，可切换降序。
- 点击进入共享歌曲列表；普通歌单成员顺序和智能歌单保存的排序继续保留。
- 专辑按名称分组，同名专辑合并。
- 歌手按完整元数据字符串分组，不拆分合作歌手。
- 标签页保留创建、改名、删除；歌单页保留普通／智能类型区分及管理入口。
- 缺失专辑、歌手使用独立的“未知”分组，避免与真实同名元数据混淆。
- 分组计数与详情使用同一成员集合，失联状态继续保留。

### 4. minibar 与完整播放页
**minibar**
- 所有业务页面共用：左封面、中间歌名与副标题、右侧播放／暂停和队列按钮。
- 副标题显示**当前行 LRC 原文**；首句前、无歌词或歌词不可读时回退歌手。
- 暂停保留当前歌词；不显示作词字段、专辑或音质标签。
- 点击封面或文字打开完整播放页；队列按钮直接打开完整队列。
- 空队列显示“未播放”，播放按钮禁用，队列入口仍可使用。
- 保持播放／暂停和队列两个按钮，不增加上一首、下一首，也不绑定完整播放页的长按布局切换。

**完整播放页**
- 两端均为独立页面，提供标准（复杂）和简洁两种布局。当前运行记住所选模式，冷启动回到标准模式。
- 标准模式长歌名自动横向滚动，歌手另起一行与歌名左对齐。可识别的多歌手元数据用 `/` 分隔，点名字进入对应歌手的歌曲页。主三键与播放模式、睡眠定时和队列分别成行，歌曲操作位于右上角。
- 沉浸模式展示封面驱动的暗色背景、大圆角封面和靠下的主三键。长按完整播放页的中央播放键进入或退出，短按仍切换播放和暂停。读屏可通过播放键的自定义操作切换。
- 向下拖动播放页时页面跟手移动，松手达到距离或速度阈值则关闭，否则回弹。系统返回、Esc 和标准播放页菜单仍提供关闭入口。
- 布局切换不重新打开音频文件，不改变队列、当前进度或播放意图。返回入口、系统返回及 Esc 保持可用，避免无法退出简洁模式。
- 两种布局均可点击封面进入独立沉浸歌词；歌词与布局模式为独立状态，返回歌词来源页时保留原模式，不互相重置。
- 背景参考封面柔化后的低饱和色、模糊渐变与深浅遮罩，保证文字和控件对比；无封面时回退主题渐变。大封面圆角、比例与留白按屏幕自适应，不照搬参考图像素；不引入波形、投放、音效或音质标识。

**随机队列的可见顺序（2026-11-14用户反馈确认）**
- 随机模式先生成本轮随机列表，完整队列展示该顺序，实际播放沿可见顺序推进；不保留另一份与展示不一致的隐藏随机顺序。
- 未播完本轮不重洗；手动重排以可见顺序为准，优先待播仍FIFO，上一首/下一首与自然结束保持一致。轮末可生成下一轮。

**共用主控制区**
- 播放页、队列页等使用共用主控制区的位置统一为上一首／播放暂停切换／下一首三键，删除独立方块停止按钮；中央播放／暂停切换必须保留。用户已明确确认此取舍。
- 保留控制器 `stop` 及停止业务能力，后台、睡眠和错误清理继续可用；用户手动停止通过更多菜单的文字项进入。此调整不删除停止控制器或改动其业务语义。

## 三、歌词、封面和定时实现

### 1. LRC 与沉浸式歌词
只读取音频**同目录、同文件主名的 `.lrc`**，不修改音乐或歌词文件。
- 支持常见分钟／秒时间戳、小数秒、多时间戳、`offset` 及元信息行。
- 同时间戳第一条为原文，第二条为译文；额外文本保留为附加行，不丢弃。
- 原文和译文左对齐，缩小字号和行距并加重字形。原文在上，译文字号更小。点按反馈采用圆角。
- 当前句高亮，周围句透明度逐级递减，顶部和底部渐隐；采用封面柔化背景、轻渐变、适量圆角及平滑过渡，深浅主题均须可读，渐隐不得遮没可交互的当前句。
- 自动跟随当前句，手动滚动暂停跟随，点击歌词跳转并恢复跟随。
- 点击歌词跳到对应时间；拖动播放进度后立即重新定位。
- 双端独立沉浸歌词显示歌词和左上角返回，移除进度、播放控制及右上角菜单。歌词明确不继承文字下划线，保持原文和译文、当前句高亮、滚动浏览与点句跳转。返回后保留进入前的标准／简洁布局。
- minibar 和完整播放页共享同一时间轴，切歌时旧异步结果不能覆盖新歌曲。

默认支持 UTF-8／BOM 和带 BOM 的 UTF-16；其他编码明确提示，不猜测转码。读取上限设为 1MiB、解析后最多 10000 个时间点，超限或损坏时降级展示，不阻断播放。

Android 通过已授权目录及文档供应商查询伴随文件，返回真实 `content://` URI；不拼接 URI、不推导真实路径、不新增全盘权限。

### 2. 封面与歌曲信息
- 只使用内嵌封面，完善缺失、损坏、超大图片回退。
- 列表使用缩略图，完整播放页按需获取大图。
- 共用有界 LRU 缓存及并发读取合并，以文件位置、大小、修改时间和目标尺寸区分缓存。
- 播放页及歌词背景复用缓存缩略图，按切歌更新；不随播放进度重复解码封面，缺失或损坏时使用主题渐变回退。
- 刷新后变更的文件失效，列表按可见范围懒加载；不预读万首原图。
- 歌曲信息只读展示：歌名、歌手、专辑、时长、文件名、格式、大小、修改时间及可用状态；缺失字段显示未知。
- 不为展示信息修改歌曲 UUID 或升级数据库结构。

### 3. 睡眠定时
- 定时入口直接打开圆盘弹窗。圆形预设仅显示数字 15、30、45、60，点按即按相应分钟数开始定时。
- 自定义时长默认先选分钟，右上 H/S 按钮切换小时与分钟盘。分钟盘选 0～59，小时盘选 0～12。圆盘支持方向键及 Home／End。
- 小时和分钟组合，总时长必须大于零，最长 **12小时59分钟**；切换单位保留已选值。
- 只累计后端可观察的实际播放时间；暂停、缓冲、装载、停止和失败期间不计，拖动进度不增加累计量。
- 到期后锁定当时歌曲，允许其自然播完；结束判断先于循环、随机和优先待播推进。
- 到期时已经暂停或失败，则结束定时并保持停止。
- 到期等待期间手动切歌会停止；取消定时后可正常切歌。
- 可取消、重设；关闭进程后不恢复。停止保留队列。

计时进入现有串行播放链，使用可注入单调时钟；取消、重设及销毁使旧回调失效，避免自然结束、错误跳过和切歌竞态造成续播。

## 七、固定样本与测量入口契约

### 样本与 check 分支

`scripts/check.ps1 -Round R6` 继承 R2～R5 的曲库/标签/筛选/队列样本、报告与全套单元/widget检查，新增 `TAG_MUSIC_R6_FIXTURES` 和 R6 工具测试；仍串行执行 Flutter。报告分别为 `library/tag/filter/queue-benchmark.json`，它们保留原来的性能类型与门禁，仅作为按需回归入口，不是每批必跑，不代表 R6 新UI或图片/歌词性能。`verify-packages.py --round R6` 加入既有 SQLite 输入哈希、Android剥离重现、Windows引擎身份及无SQLCipher分支；仍须传真实候选参数与 `--native-reference-round R1`，在下次Android构建覆盖原生输入前审计。

固定数据由 [make-r6-fixtures.py](../../scripts/make-r6-fixtures.py) 使用已生成的原创FLAC生成至 `artifacts/R6/r6-fixtures/`：

| 样本 | 固定内容与用途 |
|---|---|
| 封面 | 原创64/512/4096方形RGB渐变PNG；三种尺寸内嵌FLAC、无封面、声明PNG但内容损坏的封面FLAC；4096图按RGBA解码约64MiB，用于超大图回退与资源测量 |
| LRC基本语义 | UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM，同时间戳原文/译文/附加行，多时间戳、整数/小数秒、正负offset及元信息；正常封面/无封面/坏封面音频均带同目录同主名LRC |
| LRC降级边界 | 无BOM GB18030、无效UTF-8、损坏时间戳、恰好10000/10001时间点、恰好1048576/1048577字节；边界文件分别测解析/上限降级，不能把大文件读成功当解析成功 |
| 样本身份 | `SOURCE.json` 固定schemaVersion、原创CC0来源、音频源SHA256、每文件相对路径/长度/SHA256。已有manifest时校验，不覆盖坏样本；失败/部分目录保留后换新目录生成 |

所有歌词为原创测试文本，音频为已有原创合成音；不使用私人歌曲。Android后续每批仍放 `Download/tagmusic/<批次>/`，记录实际SAF URI与授权状态，不能把生成机路径当手机URI；推送、安装或运行须另获当批授权。

### R6性能测量与报告契约

[r6-performance.py](../../scripts/r6-performance.py) 只生成采样模板、校验原始观测与证据哈希、从原始数组复算中位数及P95，不启动应用。`check -Round R6` 创建 `r6-performance-template.json`，其中全部 `notMeasured`，**模板存在和工具测试通过不表示完成性能验证**。仅在相关性能问题或已确认测量范围需要时接入计时/FrameTiming/资源采样，不作为每个功能实现前置任务。

原始JSON保留十个独立场景，不能用聚合查询耗时填全部字段：

| 场景（performanceType） | 固定方法、计时边界与原始证据 |
|---|---|
| group / sort / search（synthetic-database） | 同一隔离万首库：编号0～9999，歌名`歌曲<编号>`，歌手为编号mod100、专辑为mod1000；每100条留一条未知歌手/专辑/修改时间；修改时间按编号mod1000形成同值。分组计数、三种排序双向、查询`歌曲9`分别记录子场景；注明生成版本/种子0、初次加载另计。计时从调用实际业务API至结果可用，排除建库和断言，校验成员/计数/稳定次序 |

报告器默认拒绝未测、缺场景、缺证据/内存、哈希不符、非法数值与覆盖输出；`--allow-partial` 仅生成 `complete=false / incomplete-not-accepted`。完整报告为 `reported-no-performance-threshold`，表示已报告而非应用性能验收通过。当前R6未决定新的速度阈值，不套R4查询/R5队列阈值；工具不能证明计时端点正确或判定可读性、流畅感及听感，体验由用户确认，计时端点仅在需要独立判断时另审。

### 2A．实施次序与文件所有权

同一个 developer 连续负责相关业务及必要调整，避免并发编辑同一导航/controller。按依赖完成排序/独立查询API、共享行及其消费者、壳层/搜索/目录和播放器兼容入口；同批不逐块回 planner 或安排测试/审查/提交。页面组完成后一次处理本批必要检查，普通缺口进入用户体验清单，具体高风险按§五定向检查。

预计涉及现有文件：`app.dart`、`library_controller.dart`、`filter_rule.dart`、`library_page.dart`、`library_search.dart`、`filter_page.dart`、`playlists_page.dart`、`playback_page.dart`、`queue_actions.dart`及对应测试。`queue_actions.dart`若仅需允许传加号图标或工具提示，保留原默认参数及原调用方；不改FIFO本身。目录管理可抽取为`library_directories.dart`供设置复用。无需修改生成代码、schema基线、原生桥、依赖或播放控制器状态机。

顺序边界：七入口和其状态容器在顺序2建立；专辑/歌手真正分组、标签详情及分组管理统一样式仍属顺序3，本单元只接入明确标注“分组浏览待接入”的页面容器，不以占位页计分组通过。共享组件在本单元至少有首页、独立搜索、现有筛选和两类歌单详情的真实消费者；顺序3详情直接复用。首页取消常驻添加/管理目录按钮后，必须同时将原有添加、单根刷新和目录状态对话框接入设置，防止过渡版本丢失唯一入口；这是顺序2壳层的必要迁接，顺序3继续完成设置和分组样式。minibar在本单元仅完成全局固定位置、空态、标题/歌手及播放暂停/队列两个按钮，点击主体可打开从现有面板提取的播放器兼容路由，进度、播放模式、停止等原能力仍可达；封面缓存、LRC副标题、R6完整播放页及主三键收口留顺序4～6，不能提前记通过。

### 2B．公共排序与持久兼容

采用最小兼容扩展：在现有`LibrarySort`末尾追加`modified`，保留四个旧成员的名称、顺序和含义。首页显式白名单只有`title/artist/modified`；筛选页沿用已保存的排序，智能编辑器继续提供原四项，`FilterPreferences()`仍是`title/false`。首页运行态默认单独改为`sort = LibrarySort.modified`、`descending = true`，不把该默认写入当前筛选或歌单，也不将全库设置变成持久设置。`filter(order: album/name)`可保留作已有内部兼容入口，首页面板不暴露它们。

`_sortTracks`须分两条明确分支：

- 旧四项逐字保留原比较语义：主值转小写比较；同值按原始文件名、歌曲UUID比较；降序反转整个比较结果。不得顺手改变空歌手/空专辑、文件名大小写、并列项或方向行为，现有智能歌单结果也依赖这些细节。
- `modified`仅比较`song.modified`的整数值。先判断null：一个未知时永远排在已知后方，**此判断不随降序反转**；两个已知且值不同时才应用升降方向。时间相同或都未知时固定按原始文件名升序，再按UUID升序，两个方向并列次序相同；不依赖Dart排序稳定性或SQLite读出顺序。不自行把0/负数再解释成null，平台规范化沿用已有入口。

不要通过列表整体`reversed`实现修改时间降序，否则未知会跑到前面、并列规则也被翻转。`selectedTracks`继续与首页使用同一排序实现，缓存失效沿用`filter/reload`并补查新API；筛选/智能仍调用旧分支。普通歌单完全绕过排序，继续按`playlistSongIds`的持久位置输出。

持久兼容要求：不改schema v4或`FilterRule.version=1`，不批量重写旧记录，保持`sortOrder`字符串与`descending`原值，未知值仍失败关闭；显式保存modified须能读回，取消编辑不得改变旧记录。仅在本批实际改变旧值读写/比较语义时，复用旧wire预置记录检查读取、保存重开和关联/顺序，不要求补齐全部UI矩阵；既有有效结果沿用。无schema变化不新迁移或重生成DDL；确需迁移须说明原因并检查旧库保留/回滚。

### 2C．独立查询与来源快照

在controller提供无副作用查询（建议`searchTracks(String text, {LibrarySort order = LibrarySort.modified, bool descending = true})`）：直接对完整`tracks`检索，与首页`query/showMissing`、当前筛选规则和已打开的歌单无关，匹配展示歌名、原文件名、歌手、专辑，沿用trim/不区分大小写contains。可用与失联记录均展示，失联行保持可识别而不能播放/入队；不静默把“全曲库”缩成可用曲。返回不可变有序快照，不直接返回可变`tracks`，不修改任何查询/排序/筛选或持久状态。

独立搜索页自有`TextEditingController`、`FocusNode`、查询、选择集合及滚动控制器，退出即释放，来源页仍挂载。现有`LibrarySearch`的输入连接/IME处理可改为回调式编辑器复用，不能继续写`library.query`；按必要性保留诊断，不引入每次击键或播放tick调用原生诊断。源库扫描/标签更新后刷新搜索结果，播放进度更新仅更新当前状态标记，不重新查询排序万首库；查询缓存至少区分库数据变化、查询和排序，不以播放通知作失效信号。

共享列表接收明确的**来源完整有序成员**和**当前可见有序成员**，状态归页面所有。单曲点击时在回调内部取当前可见结果的可用项快照，按UUID求target后调用`playSongs`；随后搜索、排序或切页不改变已有队列。单曲加号调用`addToQueue([track.queueSong])`，允许重复歌曲生成不同队列条目，连加A/B保留FIFO且不切当前歌、不重洗随机轮次。

选择集合按歌曲UUID，长按选中当前行并进入选择；右键及更多菜单提供同等入口。选择模式短按只切选择，不能启动播放；图标/菜单点击不能冒泡为行播放。全选针对当前可见成员作并集，跨查询已选项保留；标签/入队/保存歌单先按页面所属的完整来源次序提取选中成员，再在打开对话框前固定快照。不能在搜索、歌单或筛选页调用按首页排序的`library.selectedTracks`来重排来源。入队只取可用项；标签及普通歌单保存仍能保留失联UUID。成员真正从所属集合删除才清除陈旧选择，查询隐藏不清除。专用工具栏提供全选、批量标签、入队、保存普通歌单及退出，空选择禁用动作，窄屏/大字号可换行或滚动。

### 2D．共享行、定位与导航状态

共享行基础布局：44dp圆角封面，歌名16sp常规单行，副标题约12sp单行`歌手－专辑`（空值分别显示未知），右侧48dp加号和48dp更多按钮；失联以状态标记及提示表示，不用文件路径替代UUID。保留标签、加入歌单和进入多选等操作；完整只读歌曲信息在顺序4接入，此时菜单不得提供无响应的假按钮。现有`TrackCover`可接受尺寸参数复用，只给可见行懒读取，稳定key应包含歌曲/位置、大小及修改时间以使刷新后的Future失效；不在此另建第二套封面缓存，损坏/缺失图用回退，缓存与超大图完整治理留顺序4且明确未验收。

定位采用同一列表当前行序的UUID索引，不搜全库、不切页、不清查询。避免对尚未构建的远处GlobalKey调用`ensureVisible`，也不能固定乘60后忽略2倍字号。建议列表在给定字号/字体/宽度下使用**统一且计算过的itemExtent**：以实际TextStyle、TextScaler及单行TextPainter高度求歌名+副标题+间距/内边距，与60dp目标、44dp封面及48dp交互高度取最大值，行本身使用同一extent；放大字号时高度增加，正常行不另加不可计量的第三行。`ScrollController`按index×extent并夹在合法范围滚动，完成后短暂高亮当前UUID，取消旧timer并在dispose释放。库刷新、排序、查询、当前歌变化时使旧定位令牌失效，重新核对成员；目标不存在或controller无有效业务UUID时按钮禁用。高亮使用独立状态，不改变多选，播放中的主题色标记可与定位高亮共存。末行受maxScrollExtent夹取后仍须可见。

壳层按目标平台区分Android抽屉和Windows常驻栏，不能继续仅以宽度把Windows窄窗变成手机底栏；若执行已有平台检查须显式设置目标平台，避免主机平台污染结果。七入口使用稳定枚举/key，顺序为歌曲/筛选/歌单/专辑/歌手/标签/设置，不再到处写数字下标。手机抽屉触发及返回行为见本规格「导航和页面结构」；导航内容在大字号和短高度可滚动。Windows宽栏显示文字、窄栏保留Tooltip及语义名称。删除顶部软件名/阶段Chip，设置保留版本/诊断。
