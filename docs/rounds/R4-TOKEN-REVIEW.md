## 值得固化的五项必要改进

1. **少读、少传、少复述。** HANDOFF作恢复入口，按符号/必要行段补读；已知未变内容不再加载。原始日志、XML和图片留文件，模型仅接收结论/错误摘录/路径。图片从工具结果直接存档或恢复原响应，避免base64转录、整份响应回灌和重复采集。子Agent只传本批差异及必要入口，不复制整份历史。
2. **稳定操作本地批量执行，模型处理分支。** 本轮手机把定位、输入后核对、集合/数量断言、媒体状态及结果归档放进有断言的本地函数，多个动作一次执行、仅在失败或批次结束返回。不要把临时helpers.ps1整份直接升级为规范：其中也有诊断冗余与失败写法。对稳定状态减少重复快照；定位不确定/前置状态变化时保留必要观察。
3. **先最小诊断，再扩大验证。** 起播分段日志比泛查上游/SDK更快缩小信息范围；真实时长转换复现比通用Slider示例更接近问题。修改后先针对回归，候选收口才做完整检查与双端构建；不因文档变化或没有新证据反复全量验证。记录已试方法，停止原样失败路径。
4. **GUI通道和证据出口先做小规模可用性核对。** 在已授权范围内先验证代表动作的定位/输入/截图存档及完整报告导出，确认可复核后再扩大批次。UIA、XML、截图、媒体会话按断言和状态选用，不强推唯一通道。报告优先完整文件或可校验分段，不能只把长JSON放日志；本次Android报告截断正是未先验证出口造成的返工点。
5. **协作和停止状态准确、简短。** 必要Windows专用子Agent配置保留，单批交付、完成或决策点汇报；避免常规步骤反复消息、短间隔轮询和父子双方重复检查。等待只关联已知活动句柄；用户明确暂停即同步Goal及HANDOFF，真实阻塞按工具规则处理，不靠反复提醒维持active。将同一工作检查点的文档变更合并，避免微小更新和重复交接膨胀。

## 不应固化为通用规则

- 纯截图没有自动解决Windows窗口确认，前景PID和DPI物理矩形只在部分操作有效；不能保证审批通过。连续两份XML相同仍可能是稳定旧边界；滚动刷新仅是本批有效的局部方法，不应每次操作强制执行。
- 逐字符数字输入在本机验证有效；不能宣称所有ADB整串输入都失效，或逐字符能保证中文/任意输入法。保存前核对实际文本才是可复用的断言。
- All tests passed不能替代缺失的完整采样；UI可用也不能代替原生日志无错误。暂停播放便于稳定观测，不能推广到必须验证连续播放的断言。
